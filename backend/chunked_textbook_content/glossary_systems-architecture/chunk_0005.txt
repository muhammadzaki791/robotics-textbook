**Loop Rate**: The frequency at which a robot control loop executes, affecting the responsiveness and stability of robot behavior. **Machine Learning Pipeline**: The complete process from data collection to model deployment for robot learning systems. **Mapping**: The process of creating a representation of the environment, often combined with localization in SLAM systems. **Middleware**: Software that provides common services and capabilities to applications beyond what's offered by the operating system. **Modular Architecture**: A system design approach that separates functionality into independent, interchangeable modules, enabling flexible robot design. **Multi-Agent System**: A system composed of multiple interacting intelligent agents, used in multi-robot coordination. **Network Protocol**: A set of rules governing the exchange of information between robot systems, important for multi-robot communication. **Onboard Computing**: The computational resources located on the robot itself, as opposed to remote or cloud computing. **Open Source**: Software with source code that anyone can inspect, modify, and enhance, common in robotics development. **Parallel Processing**: The execution of multiple computations simultaneously, important for real-time robot performance. **Performance Metrics**: Quantitative measures used to evaluate the effectiveness and efficiency of robot systems. **Pipeline Architecture**: A system design where data flows through a series of processing stages, common in robot perception systems. **Real-Time System**: A system that must respond to inputs within strict time constraints, essential for many robot applications. **Reconfigurable Architecture**: A system that can modify its structure or behavior to adapt to new tasks or environments. **Resource Management**: The process of allocating and managing computational, memory, and energy resources in robot systems. **Robot Middleware**: Software that facilitates communication and coordination between different robot software components. **Safety Architecture**: The design of robot systems to ensure safe operation, including fail-safe mechanisms and safety protocols. **Scalability**: The ability of a robot system to handle growth in complexity, size, or workload without degradation in performance. **Scheduling**: The process of determining when and in what order robot tasks should be executed, important for real-time performance. **Sensor Fusion**: The process of combining data from multiple sensors to achieve better performance than any individual sensor could provide. **Simulation Environment**: A virtual environment used to model and test robot systems before deployment in the real world. **Software Architecture**: The fundamental structures of a robot software system and the discipline of creating such structures. **State Machine**: A model of computation used to design robot algorithms that can be in one of a finite number of states at any given time.
